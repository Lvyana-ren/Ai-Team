# Skill: Task Planning & Orchestration

## Procedure
1. Restate the requested outcome in measurable terms.
2. Identify target repository, branch, platform, environment, constraints, and exclusions.
3. Separate facts, assumptions, and unknowns.
4. Break work into deliverables with dependencies.
5. Write acceptance criteria that can be objectively checked.
6. Identify required agent roles and minimum input each needs.
7. Identify risky actions and required approvals.
8. Produce a versioned handoff.

## Task ID
Use `<PROJECT>-<NNN>`, e.g. `XENOS-001`. Never reuse an ID.

## Status vocabulary
`DRAFT`, `DISCOVERY`, `WAITING_DIRECTOR`, `DESIGN`, `APPROVED_FOR_IMPLEMENTATION`, `IMPLEMENTATION`, `REVIEW`, `REVISION`, `WAITING_ACCEPTANCE`, `DONE`, `BLOCKED`, `CANCELLED`.

## Quality checks
- No vague acceptance criteria such as “make it smooth” without measurable behavior.
- No hidden scope expansion.
- No assumed platform/API compatibility.
- No implementation authorization inferred from silence.
